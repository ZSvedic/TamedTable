# Docs & web structural refactor — Status Report

**Date:** 2026-05-26

This session set up `AGENTS.md` as the agent-agnostic entry point, ran the web package through three behavior-preserving structural refactors (test colocation, `hooks/` + `lib/` folders, controller helper extraction), and locked in `lychee` as a required status check on `main`. No behavior changes anywhere — `cli`, `core`, `headless`, and the React UI were not touched. The session also unblocked two in-flight Cloud Claude PRs that landed alongside.

## The short version

Six PRs merged: `#20` link-rot cleanup, `#21` SQL scalar recovery fix (both Cloud Claude), `#22` `AGENTS.md` + `.claude/` tracking, `#23` colocated web tests, `#24` `hooks/` and `lib/` folders, `#25` controller helper extraction, `#26` always-run lychee on PRs. The new branch ruleset `main protection` makes `lychee` a required check from now on.

`controller.ts` shrank from 760 to 668 lines. The Cucumber baseline is identical: 45 / 51 headless scenarios pass, 6 SQL parse-error and cancellation scenarios remain undefined (untouched here, same numbers as the V4 baseline). `bun test` unit tests: 73 / 73 pass.

## What shipped

**`AGENTS.md` + `CLAUDE.md` symlink.** A pointer-style guide at the repo root — about 35 lines, no duplication of `README.md` / `spec/spec.md` / `ops/conventions.md`. The only original content is a workflow rule for cross-component changes. Modern coding agents (Codex, Copilot, Cursor, …) read `AGENTS.md` natively; Claude Code reads `CLAUDE.md` so the symlink covers both. The workflow rule's TDD order was initially backwards (impl-first); corrected in a follow-up to spec → Gherkin → red tests → impl → green → PR.

**`.claude/` is now partly version-controlled.** `.gitignore` narrowed from blanket `.claude/` to just `.claude/settings.local.json` + `.claude/cache/`. The new tracked content: `launch.json` (web dev-server debug action) and `commands/run-tamedtable.md` (generalized — derives the tunnel name from `hostname -s` and the repo root from `git rev-parse`, so the same file works on any contributor's machine). Personal permission overrides stay private in `settings.local.json`.

**Web tests colocated** (#23). `controller.test.ts` and `pagination.test.ts` moved from the web package root into `src/` next to the modules they test. A `"exclude": ["src/**/*.test.ts"]` line in `packages/web/tsconfig.json` keeps the React build from picking them up.

**`hooks/` and `lib/` folders inside `web/src/`** (#24). Seven files moved: `useController.ts` and `useTheme.tsx` into `hooks/`; `browser-fs.ts`, `ports.ts`, `pagination.ts` (and its colocated test), and `theme.ts` into `lib/`. Files at the package root (`App.tsx`, `controller.ts`, `controller.test.ts`, `main.tsx`, `index.css`) are unchanged. Import paths updated in 14 files; no logic touched.

**Controller helper extraction** (#25). Four sibling files pulled out of `controller.ts`:

| File | What lives there |
|---|---|
| `controller-types.ts` | `WebControllerOptions`, `Toast`, `ChatMessage`, `WebSettings`, `CellRef`, `ActivityStatus`, `DialogKind` |
| `controller-storage.ts` | `readStoredApiKey` / `writeStoredApiKey` / `removeStoredApiKey` + the storage key |
| `controller-format.ts` | `detectFormat` + `sampleNameFromUrl` |
| `controller-messages.ts` | `userFacingMessage` + `summarizeDebug` |

The `WebController` class itself stays whole. Its methods share enough internal state (`this.journal`, `this.notify()`, `this.streaming`, `this.activeAbort`, `this.headless`) that a "compose from sub-modules" split would replace a long file with a fan-out that still threads the same state through constructors. The conservative pure-function extraction is the safe, valuable subset; `controller.ts` re-exports the moved types and helpers so the public surface is unchanged and no component file is touched.

**Lychee on every PR + required check** (#26 + ruleset). The link-check workflow's `pull_request` trigger lost its `paths:` filter so `lychee` runs on every PR, regardless of whether docs changed. The new repo ruleset **main protection** then makes `lychee` a required status check for merges into `main`, with the strict "branch must be up-to-date" policy.

**Per-component folders inside `components/` was deliberately skipped.** The plan listed it as step B of the web refactor. It would have moved eleven flat `components/Foo.tsx` files into eleven `components/Foo/` folders. Without colocated tests, CSS modules, or sub-components, the structure is scaffolding for work that isn't planned. Revisit when there's something to colocate.

## Workflow correction

The first draft of the `AGENTS.md` "Workflow rule — changing a component" section listed the order as implementation → spec → Gherkin → tests. That is backwards. The corrected order (in `AGENTS.md` and in this report) is spec → Gherkin → step definitions (red) → implementation (until green) → confirm green → PR. Refactors that preserve behavior touch only steps 4–5.
