# ui-kit — keep the original, adopt one test scenario

Compares `src/packages/ui-kit` here (43 KB) with the recreate's (43 KB). Theme
tokens and the 32-icon set are byte-identical — no visual drift. The plumbing
around them is where the recreate lost ground.

## Analysis

What the recreate lost:

- The whole sync pipeline: `sync-tokens.ts`, `sync-icons.ts`, the `sync:*`
  scripts, and the guard tests (`no-hardcoded-colors`, `icons-sync`) that keep
  the app and the marketing site sharing one palette. Its `icons.ts` still
  says "generated by sync:icons" — a comment that is now false.
- Self-containment: its `index.ts` imports `../../../marketing/tokens.json`,
  reaching outside `src/`, which breaks the "copy `src/` and run it" rule in
  CLAUDE.md.

One thing worth taking: the recreate's feature file adds "A toast can carry an
inline action". The original's `Toasts.tsx` already implements toast actions,
but no scenario covers them — a real hole in the spec.

Toast timing and behavior match otherwise; React-vs-DOM is the same
architecture swap as every other recreate UI package.
